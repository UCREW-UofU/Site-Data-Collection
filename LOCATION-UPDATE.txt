OPTIONAL EQUIPMENT LOCATION — LOCAL TEST COPY

WHAT CHANGED
- Location (optional) appears below Name when creating and editing an observation.
- One equipment entry can contain several photos; they share its name and location.
- Location appears in the system and photo lists.
- It travels with the observation in exported bundles, including emailed bundles.
- Merging groups by system, equipment name and location. Case and extra spaces in
  locations are ignored for matching. A blank location does not match a known one.
- Old v2 bundles and existing records without location remain supported.
- The merged index.xlsx has an Equipment tab with a Location column, plus a
  Location row in each equipment section on the existing system tabs.
- Populated locations appear in exported photo folders and filenames.
- Distinct locations that sanitize to the same folder name receive unique suffixes.
- No dependencies, hosting settings or database schema were changed.

RUN A SEPARATE LOCAL COPY ON WINDOWS
1. Keep the original project folder and ZIP.
2. Extract Site-Data-Collection-location.zip into Downloads. The ZIP has no extra
   outer project folder. Open the extracted folder containing package.json.
3. Open Command Prompt in that folder. With the default extraction location:
   cd /d "%USERPROFILE%\Downloads\Site-Data-Collection-location"
4. Run each command separately. Stop and share the error if any command fails:
   npm ci
   npm test
   npm run build
   npm run dev -- --port 5174 --strictPort
5. Open http://localhost:5174 and leave the terminal running.
   Port 5174 uses separate browser storage from the original localhost:5173 copy.
   It will initially have no sites or photos. Create a sample site.
6. For a production-build/offline check after the above, stop the dev server
   with Ctrl+C, then run:
   npm run preview -- --port 4174 --strictPort
   Open http://localhost:4174. This is another separate browser storage location.

GITHUB UPLOAD — AFTER LOCAL CHECKS AND REVIEW
1. Use the separate Site-Data-Collection-location-changes.zip download.
2. Extract it; it contains only changed source files and documentation.
3. On GitHub, create a branch named add-photo-location from the current main.
4. Select Add file > Upload files on that new branch.
5. Drag the CONTENTS of the extracted changes package into the upload area.
   Preserve the src folders. Do not upload the ZIP or its enclosing folder.
6. Commit with message: Add optional equipment location.
7. Create a pull request from add-photo-location to main; review Files changed.
8. Merge only after local tests and team review. If main changed since the
   original ZIP was downloaded, reconcile those changes before merging.
9. Confirm the live hosting setup before deployment. DEPLOY.md refers to a
   different repository, so GitHub upload is not confirmed to publish the site.
10. Build from the updated source before deployment; do not deploy the old dist
    folder from the original download. Do not upload node_modules to GitHub.

Use the updated version for both capture and merging. The old merge app does
not understand locations and can combine equipment from different locations.
